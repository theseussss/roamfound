   2.6.9. 改动分级纪律（任何改动前先判级）

   任何"改"的动作前，先判断改动级别，并同步判断本次改动是在既有结构中融入、需要先提结构重构，还是落入追加式堆放。**能低不高**，升级前必须自问一次。
   
   | 级别 | 动作范围 | 何时用 | 代价 |
   |:---|:---|:---|:---|
   | **L1 布局调整** | 挪位置 / 合并或拆分段落/表 / 调整顺序，**原文字不改** | 论证顺序错位 / 信息架构不对 | 低 |
   | **L2 措辞微调** | 同义替换 / 句式重组 / 连接词修正 / 术语统一 | 表述不精确 / 有歧义 / 文风偏 | 低-中 |
   | **L3 局部重写** | 段落或小节从原有素材重新组织并可扩写 | 论证有缺环 / 证据要换 / 观点要重述 | 中 |
   | **L4 整节/整文重建** | 从提纲起重建，原文仅作参考 | 原文与目标结构根本错位 | 高 |
   
   **默认姿态**：能 L1 不 L2、能 L2 不 L3、能 L3 不 L4。动手前自问一次"这里真的要升一级吗？"；若升级牵涉 TOC、章节、话题目录、root 标签或角色升级，先按结构权规则提方案等用户批准。修改模板、占位注释、生成文档提示语和版本迭代文本时，先把提示语当作约束读取并遵循；只有任务明确要求修改提示本身，才按 L1-L4 判级增量改写。
   
   **二阶反思**：贴 L1 标签时查是否掩盖了隐性 L3（例：表 3/4 合并看似布局调整，实则牵连材料节奏 → 是 L3）。"代价低"只在机械层面成立，认知层面可能反而高；若改动只是把新材料塞到段末，按 smarter-project 的追加式堆放判据必须停止，改为融入既有结构或先提出结构重构。若一组内容只是被并列列出，而其中实际存在上层/下层、整体/部件、目标/路径、概念/例证等承载关系，也不能按 L1 排序处理，应先恢复真实结构再写。
   
   **与 SKILL.md §2.1 话题的关系**：§2.1 话题讲结构 vs 内容的优先级；本节讲改动的幅度级别。两者正交——先判级（本节），再按级内守结构纪律（SKILL.md §2.1 话题），并继续套用结构权审批与融入/重构/追加三分法。
