# 第一性原理

> **一句话**：剥离继承性假设，回到当前问题中最基础、最可靠、最少依赖未经验证前提的事实、约束与机制，再从这些底层要素出发重新推导最小可行方案
> **适用触发**：既有方案感觉受限、移植经验可能不适用、面对全新问题、优化已到瓶颈、需要判断“本质到底是什么”时

## 1 核心原理

任何复杂系统、方案或判断，通常都建立在一组底层事实、约束、机制和价值选择之上。第一性原理的核心不是“从零开始”，也不是简单地把事物拆成最小组件，而是：

1. **剥离继承性假设**：识别哪些判断来自惯例、类比、行业默认、个人经验或未经验证的前提。
2. **回到底层可靠起点**：找到当前问题中足以支撑推导的基本事实、强约束、关键变量、因果机制和边界条件。
3. **重新推导**：从这些底层要素出发，重建更少假设、更高解释力、更可验证的方案。

第一性原理中的“第一”，不是绝对意义上的“宇宙终极原子”，而是指：**在当前问题中，已经足够基础、足够可靠、足够少依赖未验证前提，能够作为推导起点的要素**。

常见通俗化理解可概括为“分解 → 重建”。但在实际问题解决中，这个过程应扩展为：

> **锚定现实 → 重置问题 → 分解到底层要素 → 探测行为空间 → 最小可行重建 → 验证迭代**

这个操作化版本补足了经典表达中的三个空白：

- **空白一：怎么剥假设？**  
  步骤 1-2 通过事实化锚定、假设识别、认知重置，替代笼统的“质疑你的假设”。

- **空白二：分解到什么程度？**  
  步骤 3 不只寻找“原子组件”，还寻找事实、约束、机制、变量、关系、边界条件与涌现性质，避免把第一性原理误用成普通拆解。

- **空白三：找到底层要素后做什么？**  
  步骤 4-5 通过杠杆点、相变点、失效边界、敏感变量和最小可行重建，把分析转化为行动。

## 2 操作步骤

### 步骤 1 · 问题事实化

**对象**：问题陈述本身，而不是研究对象。

**动作**：把叙事性、判断性、情绪性的问题描述，转换为可验证、可证伪、可比较的事实陈述。

| 叙事性描述 | 事实化后 |
|:---|:---|
| “我们成本太高” | “单位成本 ¥47，竞品 A ¥31，用户支付意愿 ¥38” |
| “这篇论文论证太弱” | “核心主张有 3 个，其中 2 个缺少推论保证” |
| “用户体验不好” | “注册到首次使用的完成率 23%，第 3 步流失 61%” |
| “团队协作效率低” | “需求确认平均耗时 5.6 天，返工率 32%，跨团队等待占总周期 41%” |

**关键动作**：区分五类陈述。

| 类型 | 定义 | 处理方式 |
|:---|:---|:---|
| **已验证事实** | 有数据、观察、记录或可靠证据支持 | 可作为后续推导基础 |
| **强约束** | 短期内难以改变的资源、时间、法律、物理、能力或制度边界 | 必须纳入重建 |
| **待验证假设** | 当前合理但尚未证实的判断 | 标记，后续设计验证 |
| **推论** | 从事实或假设推出的结论 | 检查推理链是否成立 |
| **价值判断** | 关于“好/坏/应该/值得”的选择 | 交给价值、战略或伦理框架处理 |

**产出**：

- 一组事实命题
- 一组强约束
- 一组待验证假设
- 一组被剥离的判断性表述

**检验**：

- 每条陈述能否被独立验证？
- 是否仍含有“太”“不够”“应该”“明显”“本质上”等判断词？
- 哪些内容其实是假设，却被误当成了事实？
- 问题被事实化后，原始问题是否已经发生变化？

---

### 步骤 2 · 认知重置（重新提问）

**对象**：你对问题的认知框架本身。

第一性原理经常不是更用力地回答原问题，而是发现：**原问题的问法本身带着未经检查的框架**。

**三个认知操作**：

#### 1. 去锚定

放下当前问题中的默认框架。

示例：

- “也许这不是成本问题，而是价值密度问题。”
- “也许这不是增长问题，而是留存问题。”
- “也许这不是执行力问题，而是目标函数冲突。”
- “也许这不是用户不理解，而是产品承诺本身不清楚。”

#### 2. 时间尺度切换

不要只从当前时点看问题，而是在不同时间尺度下重问：

| 时间尺度 | 追问 |
|:---|:---|
| **短期生存** | 现在最硬的约束是什么？现金、时间、风险、资源哪个最紧？ |
| **中期结构** | 哪些瓶颈会持续限制系统表现？ |
| **长期不变量** | 3-10 年后仍然重要的事实、需求或机制是什么？ |

时间尺度切换的目的不是忽略短期，而是区分：

- 什么只是暂时噪音？
- 什么是阶段性约束？
- 什么是长期稳定的底层规律？

#### 3. 未知出发

主动承认“我真的不知道”，从真正的无知开始，而不是从既有解释开始。

可用提示语：

- “如果我完全不知道这个行业惯例，我会怎么理解这个问题？”
- “如果现有方案不存在，我会从哪些事实开始设计？”
- “如果类比失效，这个问题还剩下哪些确定事实？”
- “我现在认为理所当然的东西，哪些其实只是历史遗留？”

**产出**：一个重新提出的问题。

**示例**：

| 原问题 | 重置后的问题 |
|:---|:---|
| “如何降低客服成本？” | “为什么用户需要客服？哪些问题本不该发生？” |
| “如何提升内容产量？” | “用户真正需要更多内容，还是更高密度的信息？” |
| “如何提高转化率？” | “用户在决策前缺少什么事实、信任或动机？” |
| “如何让团队更高效？” | “团队协作中真正稀缺的是信息、决策权、注意力还是信任？” |

**检验**：

- 新问题是否去掉了原问题中的至少一个隐含假设？
- 新问题是否比原问题更底层、更可验证或更接近机制？
- 新问题是否允许出现与原方案完全不同的解法？
- 如果新问题只是原问题的同义改写，重置还没完成。

---

### 步骤 3 · 底层要素分解

**对象**：研究对象、系统、方案或论证本身。

**动作**：把系统拆解为当前问题下的最小充分解释要素，而不只是拆成“组件”。

第一性原理分解的不只是物理部件，还包括：

- 基本事实
- 关键变量
- 因果机制
- 强约束
- 资源边界
- 时间边界
- 信息流
- 激励结构
- 关系结构
- 反馈回路
- 失效条件
- 涌现性质

**分解提示**：

| 方向 | 追问 |
|:---|:---|
| **事实** | 有哪些确定为真的观察或数据？ |
| **变量** | 哪些因素变化会影响结果？ |
| **约束** | 哪些条件短期内不可改变？ |
| **机制** | 结果是通过什么因果路径产生的？ |
| **关系** | 要素之间如何相互影响？ |
| **边界** | 在什么条件下推导会失效？ |
| **目标函数** | 系统实际在优化什么？ |
| **激励** | 参与者被什么驱动？ |
| **反馈** | 行动结果如何反过来改变系统？ |

**递归检验**：

对每个候选要素追问：

1. 它能否被更基础、更可靠的事实、约束或机制解释？
2. 继续拆解是否会提高解释力或决策质量？
3. 它是事实，还是假设、推论、类比、经验规则？
4. 它对当前问题是否必要？

当继续分解不再显著提高解释力、预测力或行动质量时，可以停止。第一性原理追求的是**当前问题下的最小充分解释集**，不是无限下钻。

**涌现性检查（必做）**：

原子化或底层分解完成后，必须检查：

> 要素组合之后，是否出现了单个要素不具备的新性质？

示例：

| 系统 | 涌现性质 |
|:---|:---|
| 水分子系统 | 流动性、表面张力 |
| 团队 | 信任、默契、士气、协同效率 |
| 产品 | 用户体验、品牌感、使用习惯 |
| 市场 | 网络效应、流动性、信任结构 |
| 论证 | 说服力、解释闭环、可信度 |

发现涌现性质后，应将其标记为独立条目，与底层要素并列，而不是附属于某个单一组件。

**产出**：

- 底层事实清单
- 强约束清单
- 关键变量清单
- 因果机制清单
- 关系/反馈结构
- 涌现性质清单
- 待验证假设清单

**检验**：

- 是否只拆出了“组件”，却没有拆出机制、约束和关系？
- 是否把经验判断误当成了基本事实？
- 是否识别了组合后才出现的整体性质？
- 是否能解释“为什么系统会这样运作”，而不只是描述“系统由什么组成”？

---

### 步骤 4 · 探测行为空间（扳机点与极限边界）

**对象**：步骤 3 产出的底层要素及其组合关系。

**动作**：探索系统中哪些变量可以改变，改变后会发生什么，以及在哪些条件下系统会失效。

**四类探测**：

| 类型 | 问什么 | 找什么 |
|:---|:---|:---|
| **杠杆点** | 哪里小投入 → 大变化？ | 效率：资源应该集中到哪里 |
| **相变点** | 哪里量变 → 质变？ | 非线性：系统行为的断裂处 |
| **失效边界** | 哪里假设崩塌？ | 风险：不能碰的极端条件 |
| **敏感变量** | 哪个变量变化会最大幅度影响结果？ | 优先级：最该验证、监控或干预什么 |

**典型追问**：

#### 杠杆点

- 哪个变量改变 10%，结果变化最大？
- 哪个环节的小修正能消除大量后续成本？
- 哪个约束一旦解除，系统能力会明显释放？
- 哪个行动可以同时影响多个关键变量？

#### 相变点

- 哪个指标跨过阈值后，系统行为不再线性？
- 用户数、密度、规模、频率、信任、流动性是否存在临界点？
- 低于某个水平时系统不可用，高于某个水平时系统突然变好？
- 哪些增长不是平滑发生，而是跨过门槛后突然发生？

#### 失效边界

- 哪个前提一旦不成立，整个方案会失效？
- 哪个变量超过上限后，收益会变成风险？
- 哪些外部条件变化会让原推导失效？
- 最坏情况下，系统会以什么方式崩溃？

#### 敏感变量

- 哪些变量最值得优先测量？
- 哪些假设最值得优先验证？
- 哪些指标应被持续监控？
- 哪些变量不重要，可以暂时忽略？

**产出**：一张行为空间地图。

地图至少应包含：

- 可动变量
- 高杠杆区域
- 非线性阈值
- 失效边界
- 高风险假设
- 优先验证项

**检验**：

- 地图上是否同时有“高回报区”和“危险区”？
- 是否识别了至少一个关键阈值或边界条件？
- 是否知道哪些变量值得动，哪些变量不值得动？
- 是否知道哪个假设一旦错了，方案整体会崩？
- 如果地图只有“机会”没有“风险”，探测还不完整。

### 步骤 5 · 最小可行重建

**动作**：从底层事实、约束、机制和行为空间出发，重建最小可行版本。

这里的“最小可行”不只指产品语境中的 MVP，也可以是：

| 场景 | 最小可行重建 |
|:---|:---|
| 产品 | 最小可用产品、最小功能闭环 |
| 商业 | 最小可行商业模式、最小盈利闭环 |
| 论证 | 最小严密论证链 |
| 研究 | 最小解释模型、最小实验设计 |
| 组织 | 最小协作结构、最小决策机制 |
| 战略 | 最小战略假设集、最小行动组合 |
| 个人决策 | 最小行动方案、最小风险试验 |

**约束**：

只带回经步骤 3-4 支持的必要要素。不是“尽量少”，而是：

> 少到再少一个，核心功能、关键指标或风险边界就会发生不可接受的变化。

**重建原则**：

1. **必要性**：每个组件、动作或规则都必须对应一个底层事实、约束或机制。
2. **可验证性**：关键假设必须能被测试，而不是只能被相信。
3. **低负担**：避免把历史包袱、行业惯例、装饰性流程带回系统。
4. **边界清晰**：明确该方案在哪些条件下成立，在哪些条件下失效。
5. **可迭代**：运行后产生新事实，进入下一轮事实化。

**最小性检验**：

对每个要素追问：

- 去掉它，核心功能是否崩溃？
- 削弱它，关键指标是否出现不可接受下降？
- 替换它，风险是否明显上升？
- 它是必要条件，还是历史遗留？
- 它是底层机制需要的，还是惯例要求的？
- 它是否只是为了让方案看起来完整？

**假设账本（必做）**：

重建时记录所有关键假设。

| 假设 | 依赖的事实/机制 | 风险等级 | 验证方式 | 失效后怎么办 |
|:---|:---|:---|:---|:---|
| 用户愿意为 X 付费 | 已有访谈、竞品价格、支付意愿数据 | 高 | 预售/定价实验 | 调整价值主张或目标用户 |
| 成本可随规模下降 | 材料成本占比、供应商报价 | 中 | 小批量试产 | 改工艺或换供应链 |
| 团队能在 2 周内交付 | 历史交付周期、当前人力 | 中 | 里程碑跟踪 | 缩范围或增资源 |

**迭代入口**：

MVP、实验、论证或方案运行后，会产生新事实：

> 新事实 → 回到步骤 1 → 重新事实化 → 更新假设账本 → 修正底层要素 → 调整重建方案

第一性原理是循环框架，不是单程推理。

## 3 适用条件

适合使用第一性原理的场景：

- 既有方案感觉受限，“一直这么做”可能隐含过时假设
- 从另一个领域移植经验，类比推理可能不适用新场景的底层条件
- 面对全新问题，没有可靠的既有方案
- 优化已到瓶颈，增量改进不够用
- 多方争论无法收敛，需要回到基本事实层检查前提差异
- 需要判断“这个东西的本质到底是什么”
- 需要重新设计产品、组织、商业模式、论证、研究路线或决策方案
- 当前问题被情绪性、叙事性或价值判断语言包裹，需要先还原为事实
- 怀疑行业惯例、经验法则或类比对象正在失效
- 需要识别关键杠杆点、相变点或失效边界

不适合优先使用的场景：

- 问题很小，直接执行比深度重构更划算
- 现有方案已经足够有效，只需要局部修补
- 时间极度紧迫，无法完成基本验证
- 问题主要是价值冲突，而不是事实、机制或约束不清
- 缺少必要领域知识，且无法获得外部专家校正

## 4 局限

- **时间密集**：完整走完五步需要大量认知投入，轻量问题不值得动用。

- **容易过度下钻**：第一性原理不是无限追问“为什么”，而是找到当前问题下足以支撑推导的最小可靠起点。继续分解若不能提高解释力、预测力或行动质量，就应停止。

- **涌现性盲区**：分解天然倾向还原论，而系统常有其组成部分没有的整体性质。步骤 3 的涌现性检查和步骤 4 的行为空间探测可以部分弥补，但无法完全消除。

- **依赖领域知识**：识别什么是真正的底层事实、强约束和关键机制，需要足够的领域素养。新手容易把“第一层拆解”误认为“第一性原理”。

- **重建偏好**：容易诱导人推倒重来。但有时既有方案 90% 是对的，只需要修补。使用前先问：现有方案的问题是根基性的，还是局部性的？

- **可能低估历史经验**：经验和惯例未必都是错的，它们可能是长期试错后的压缩结果。第一性原理应审查经验，而不是自动否定经验。

- **不替代价值判断**：第一性原理不能替你选择终极价值，例如“增长还是利润”“效率还是公平”“安全还是速度”。它能做的是澄清不同价值选择背后的事实、约束、代价和后果。

- **验证成本可能很高**：有些底层假设需要实验、数据、专家判断或长期观察才能验证。没有验证机制时，所谓“第一性原理”可能只是更自信的猜测。

## 5 组合

- **`[[toulmin-model]]`**（图尔敏论证图式）：用第一性原理发现底层事实、约束和机制，用图尔敏把发现组织成严格论证。第一性原理分解现实，图尔敏分解论证——分析与表达互补。

- **MECE**：确保步骤 3 的分解完整性，避免重要类别遗漏或重复。第一性原理告诉你“拆到底层可靠起点”，MECE 帮你检查“拆全了没”。

- **系统思维**：补充涌现性、反馈回路、延迟效应和整体行为。第一性原理负责剥离假设和底层推导，系统思维负责追问“组合之后整体如何运作”。

- **`[[assumption-mapping]]`**：将步骤 1-5 中出现的关键假设显性化，按重要性和不确定性排序，决定优先验证什么。

- **`[[mvp]]`**：用于产品、商业或实验场景中的最小可行重建。第一性原理负责确定“什么是真必要”，MVP 负责快速验证“是否真的成立”。

- **`[[ooda-loop]]`**：用于快速迭代场景。第一性原理提供底层推导，OODA 提供观察、判断、行动、再观察的循环节奏。
