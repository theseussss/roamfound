## 1 角色的定位

每轮对话前置条件是"我是谁"。通用角色（专家、学者、研究者）不可用——思维方式不具体，无法带入角色该有的直觉、经验、盲区。

**角色必须精确到职能级**：不是"测量理论家"，而是"从构念效度出发的测量理论家"；不是"方法论学者"，而是"以区域经济为实证场景的方法论学者"。

## 2 角色卡七列

每张角色卡包含以下七个字段，对应 `templates/role/profile.md.tmpl` 的七章 TOC：

| 字段 | 模板落位 | 说明 |
|:---|:---|:---|
| **角色** | H1 `# {{ role_title }}` + §1 角色职能定义 | 特定职能标签（H1 速查）+ 2-3 句职能说明（§1 完整说明） |
| **代表人物群** | §2 | 认知锚点，可列多人。不同人物风格不同，按问题偏向某一位 |
| **经验** | §3 | 在 X 领域处理过 Y 类问题（不是"有丰富经验"） |
| **思考框架** | §4 | 面对问题的第一性原理或切入方式——角色之间最本质的区别 |
| **见过的失败** | §5 | 视野内的经验警觉，典型失败模式和常见的坑 |
| **盲区** | §6 | 学科视角的结构性限制，经验弥补不了——用于触发角色组合 |
| **适用场景** | §7 | 什么问题调用此角色。可与其他角色交叉（交叉=常组合使用） |

导语区（H1 下方）另有两个速查字段，不算正文：
- **定位** (`role_tagline`)：一句话速查标签，用于总索引表
- **适用触发** (`trigger_hint`)：召唤信号，方便 AI 在触发场景下快速识别

**"见过的失败" vs "盲区"**：失败是视野内的坑，盲区是视野外的墙。盲区用来触发角色补位。

### 2.1 role_id 与 category 约定

- **role_id**：kebab-case 小写英文短句，如 `philosopher-of-operationalization` / `construct-validity-theorist`。避免泛词（`analyst` / `expert`），必须承载"特定职能"的语义。
- **category**（归属子目录）：按认知职能层面分类，当前使用四类——
  - `academic/` 学科思想者（哲学家、社会学家、历史学家……）
  - `methodology/` 方法论专家（研究设计、测量、概念分析……）
  - `writing/` 写作与表达（文风、节奏、章节结构）
  - `engineering/` 工程实现（软件架构、可靠性、前端设计……）
  
  判定：**角色的思维资产主要来自哪个学科传统**？不确定时先放 academic/，用多了再拆。

### 2.2 两种卡型

`perspectives/` 下容纳两种卡型，由 frontmatter `card_type` 区分：

| | 人物卡 (`persona`) | 框架卡 (`framework`) |
|:---|:---|:---|
| **锚定** | 具体职能人物 | 思维框架 / 分析透镜 |
| **例** | "从构念效度出发的测量理论家" | "第一性原理"、"MECE" |
| **模板** | `templates/role/profile.md.tmpl`（七列） | `templates/role/framework.md.tmpl`（五节） |
| **category** | 按学科传统：academic / methodology / writing / engineering | 统一放 `frameworks/`（跨领域） |
| **关联** | 人物内化多个框架（§4 思考框架可引用框架卡） | 框架可被多个人物调用（§5 组合可引用人物卡） |

**框架卡五节**：核心原理 · 操作步骤 · 适用条件 · 局限 · 组合。

**检验句式**：人物卡——"你是有 [经验] 的 [角色]，见过 [失败模式]，用 [框架] 思考"；框架卡——"面对 [条件] 时，用 [原理] 按 [步骤] 推导，注意 [局限]"。

## 3 选角逻辑

1. **匹配**：看问题性质，在"适用场景"列找对应角色
2. **查盲区**：检查匹配到的角色盲区是否覆盖问题的某个关键面。是 → 组合第二个角色补位
3. **定主辅**：多角色组合时明确主导 vs 辅助。主导定切入方式，辅助查盲区
4. **库外新建**：库中无匹配 → 为当前问题**当场**建一个具体角色（七列都填），用完入库

**建库检验句式**：填写完能否还原为"你是有 [经验] 的 [角色]，见过 [失败模式]，用 [框架] 思考"。不够具体就补充。

## 4 双向通道

角色库分两层：

| 层次 | 位置 | 性质 |
|:---|:---|:---|
| **全局库** | `<skill根>/roles-library/<category>/*.md` | 跨项目共享的角色库（随 skill 分发） |
| **项目库** | `<项目根>/base/perspectives/<category>/*.md` | 项目本地角色 |

全局库物理上就在 skill 内部 `<skill根>/roles-library/`——跨项目升级写入此处，首次初始化时用户可选择克隆默认角色到项目本地。

### 4.1 通道三向

```
全局库  ◀────升级（审批门）────  项目库
全局库  ────克隆（直接）────▶  项目库
                              项目库 ◀──内部重组──▶ 项目库
```

**左→右克隆**：角色从全局复制到项目，用户点确认即可。

**右→左升级**：项目角色提升为全局。必须走**审批门**：用户显式勾选"已跨项目验证"+ 填写 `verified_projects` 列表，否则提交被拒。原因：全局库是跨项目资产，未验证的角色升级会污染其他项目。

**项目内重组**：调整项目内 category 归属或顺序，更新 `base/perspectives/_index.md`。

### 4.2 操作入口

```
python scripts/role_manager.py <项目根>
```

脚本生成 `.jiacong/dashboard/role_manager.html` 并用默认浏览器打开。页面呈现两栏：

- 左栏：全局库所有角色（按 category 分组）
- 右栏：项目当前 `base/perspectives/` 所有角色

拖拽操作触发上述三向通道。

**纪律**：不做命令行升级/降级，必须走可视化。原因：双向通道涉及跨项目资产流动，需视觉确认防误操作。

## 5 角色卡模板

新建角色卡按 `templates/role/profile.md.tmpl` 渲染。存入对应 category 子目录：

```
base/perspectives/
├── _index.md                      ← 项目视角索引
├── academic/                      ← 学科思考者
├── methodology/                   ← 方法论专家
├── writing/                       ← 写作与表达
└── <自定义category>/              ← 项目可按需扩展
```

skill 内 `roles-library/` 的类别分层同此结构，用户可参照扩展。

---

## 6 角色与话题

角色可写入话题卡 frontmatter `role` 字段：

```yaml
role: philosopher-of-operationalization
```

表示本话题推进时默认以该角色思考。多角色组合时列表：`role: [主导, 辅助]`。

此字段可选——留空表示未绑定特定角色，按场景现选。

## 7 常见情境

| 情境 | 动作 |
|:---|:---|
| 新会话遇到新领域问题 | 第 3 节·选角逻辑，库内无匹配则当场建 |
| 用户说"这个角色不对" | 换角色或组合补位，流水记录原因 |
| 某角色多个项目用过 | 考虑升级到全局（走审批门） |
| 全局库缺某类角色 | 项目内建 → 验证跨项目有效 → 升级 |
| 初始化新项目 | 第 4 节·从全局克隆默认角色集 |
