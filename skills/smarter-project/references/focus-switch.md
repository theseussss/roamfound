# 焦点切换

> ⚠️ **执行规约（非知识文档）**。焦点动作必须落到 `.jiacong/focus.json` + `focus_breadcrumb.py` 输出，不是口头声明。
> **最小执行门**：未完成焦点遇切换 → 先逐字输出附录 A 警告 → 用户显式"切换到 X" → 写 `.jiacong/focus.json` → `python focus_breadcrumb.py <项目根>` 验证链路 → 写流水。
>
> **锚定**：SKILL.md §1.3 每轮循环（§1.1 结构权归用户）
> **加载时机**：用户要求切换焦点，或会话开始需重建焦点上下文时。
> **读完即应能**：判断焦点层级、守回溯纪律、正确写入 focus 字段。

---

## 1 焦点机制

`.jiacong/focus.json` 是当前焦点权威源，核心字段为 `topic_id`。旧 `.claude/focus` 是单行 legacy fallback，可读取，可在需要兼容旧工具时显式 mirror。

| 格式 | 语义 | 示例 |
|:---|:---|:---|
| `NNN` | 认知层焦点（话题级） | `112` |
| `NNN:TMM` | 旧格式兼容：读取时只取话题 `NNN`，任务进入 `tasks.md` | `112:T01` |

**多轨道可并行，焦点始终唯一**。多个话题/任务可以同时处于活跃状态，但当前注意力只指向一个。

---

## 2 面包屑

面包屑沿 parent 链从顶层话题（`parent = null`）追溯到当前焦点，输出完整路径。

```
python scripts/focus_breadcrumb.py <项目根>
```

输出示例：

```
🎯 001 目标 > 100 项目管理 > 112 脚本工具链
```

每轮回复首段展示短面包屑，让 AI 自身与用户都能从当前焦点快速回到上文。短面包屑是每轮固定格式，不等同于完整地图感反馈；完整地图感仍按交互协议 §2.6.8 的复杂任务触发节奏输出。

> 固定格式的权威定义见 SKILL.md §1.3 每轮循环，本节补充执行要求。

固定首段格式：

```text
当前位置：父话题 > 当前话题:TNN
层级判断：独立 / 下属 / 支线 / 关联
本轮归位：scratch / card / tasks / logs / doc
```

执行要求：
- `当前位置` 每轮首段必有，来自 `.jiacong/focus.json` + `focus_breadcrumb.py`（旧 `.claude/focus` fallback）
- `层级判断` 在新话题、切焦点、话题归位时必有；普通延续轮可写"延续当前焦点"
- `本轮归位` 在有写入、决策、沉淀或执行动作时必有；纯回答可写"无写入"

---

## 3 切换流程

焦点切换前先过**三级判定**（权威定义见 SKILL.md §1.3 每轮循环，本节补充切换场景的判定标准）：

| 层级 | 动作 | 判据 |
|:---|:---|:---|
| **只读** | 发现关联但不操作 | 不需要在目标话题写任何内容 |
| **侧写** | 在目标话题 scratch 追加简短条目，不切焦点 | 只需记一笔（状态更新、发现、待办），无需展开讨论 |
| **切焦点** | 进入目标话题深入推进 | 需要展开讨论或改结构 |

只有第三级才触发下方切换流程。侧写时保留双向索引：当前话题 scratch 记录 `→ 侧写 NNN：补充了 XX`，目标话题 scratch 记录 `← 来自 NNN/SNNN：XX`。

**触发**：
- 用户原话："切到 XXX"/"先看 NNN 这个话题"/"焦点换一下"
- AI 结束当前话题后主动询问"接下来关注哪个？"
- 新建话题后用户说"就先做这个"

**前置校验**：
- 目标话题已存在？否 → 先建（见 `topic-lifecycle.md` §3 新建话题）
- 从目标沿 parent 链能追到顶层话题（`parent = null`）？否 → parent 链断裂，需先修复

**执行**：

1. 将目标话题 ID（`NNN`）写入 `.jiacong/focus.json` 的 `topic_id` 字段；如需兼容旧工具，才同步 mirror 到 `.claude/focus`
2. 调 `focus_breadcrumb.py` 重新渲染面包屑
3. 不在入口文档内手写焦点显示行；入口文档只指向 `.jiacong/focus.json`，面包屑由脚本实时渲染
4. 读目标话题的 `card.md` + `scratch.md` 末尾 10 行，建立本话题的认知上下文
5. 流水追加切焦点行

---

## 4 回溯纪律

切焦点**前**必须完成三件事，保证旧上下文不被丢弃：

1. **记本轮流水**（三维标签 + 最佳原话）
2. **当前 scratch.md 加时间戳段**（即使只写一行"切走"）
3. **新焦点能沿 parent 链追回旧上下文**（parent 链完整）

没做完这三步就切焦点 = 违纪。上下文丢失后回溯成本远高于多写三行。

---

## 5 切换警告

未完成焦点遇到切换请求时，逐字输出警告：

```
⚠️ 焦点切换请求
当前焦点 [当前ID] 未完成。

切换后果：
- 当前推导上下文将冻结，下次切回需重建认知现场，存在信息衰减
- 若切换频繁，两条轨道均将长期停留在半完成状态，无法形成可交付产出

若仍要切换，请明确回复：切换到 [目标ID]
否则继续推进当前焦点。
```

**判定"未完成"**：当前话题卡 status 仍为 ⏳ 进行中，且讨论卡 status 非 📦 已封存。

用户明确回复"切换到 X" → 按第 3 节执行切换。
用户沉默或回答含糊 → 视为继续推进当前焦点，不切。

---

## 6 冷启动

会话开始时 `.jiacong/focus.json` 不存在或为空，且旧 `.claude/focus` 也无可读 fallback：

1. 提示用户确认焦点
2. 若用户有明确意图 → 按第 3 节切换流程写入 focus
3. 若用户只是闲聊或无焦点 → 保持空 focus，不强写

---

## 7 焦点与话题收敛

话题收敛（见 `topic-lifecycle.md` §6）后焦点常需切换：

- ✅ 已关闭 / ⏸️ 已搁置 → 通常切到下一个活跃话题
- 🔻 已推翻 / 🗑️ 已废弃 → 切到上游话题或替代话题

收敛本身不自动清空 focus——由用户决定下一步去哪。
